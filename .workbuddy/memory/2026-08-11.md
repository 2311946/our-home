## 修复：搜索"没搜索到也没定位到"的根因
- 根因 1（搜不到）：`doSearch` 原来查的是 **Supabase** (`SUPA_URL`) 的 chat_messages，但聊天消息实际全部存在 **PocketBase** (`PB_URL`，saveToCloud/loadCloudChat 都走 PB)。Supabase 里没有最近的消息 → 搜不到。
- 根因 2（定位不到）：即使搜到，原 `doSearch` 按 `m.role==='user'` 判定角色；但 PB 里**群聊消息的 `role` 字段存的是中文名（"顾言"/"裴寂"/"宣宣"…），不是 user/ai**，导致算出的 role/character 与 `render()` 渲染出的气泡对不上，匹配失败。
- 改动（`js/all.js`）：
  1. `doSearch` URL 改为查 PB（`/api/collections/chat_messages/records`），用 PB 过滤语法 `filter=(character="X") && (content~"kw")`，群聊用 `((character="group") || (character~"group_")) && (content~"kw")`；去掉 Supabase 鉴权头，前置校验改查 `PB_URL`。
  2. `doSearch` 群聊结果的 role/character 改用与 `loadCloudChat` 完全一致的 `nameMap`（中文名→角色 id），保证和渲染气泡的 `data-role/data-char` 一致。
  3. `loadCloudChat` 群聊过滤范围从只查 `character="group"` 扩大到 `((character="group") || (character~"group_"))`，并兼容 `group_*`（AI 回复）映射（实测当前库无 group_* 记录，该分支为无害兼容代码）。
- 实测验证：用真实 PB 数据跑端到端，群聊 311 条（perPage=500 全加载），多个关键词的搜索结果 role/char/content 与渲染气泡 100% 匹配（未匹配 0）。
- 注：`js/all.js.bak` 为备份文件，index.html 加载的是 `js/all.js`（已删除该 .bak）。

## 紧急修复：PocketBase 不支持多条件 AND 过滤
- 现象：用户反馈"搜索报错、搜不到哈喽"。排查发现：之前 `doSearch` 用 `filter=(character="yan") && (content~"kw")` 组合过滤，但**该 PB 版本忽略 `&&`/`||` 之后的所有条件（只认第一个条件）**，导致 `content~` 被丢弃，搜索退化为"返回该角色全部最新 N 条"，老消息（如 2026-03-25 的"哈喽"）不在最新 300 条里 → 搜不到。
- 验证：(character="yan")&&(character="peiji") 返回 30620（应为 0）；(content~"哈喽") 单独返回 48（正常）；证明只认首条件。
- 修复（`js/all.js` `doSearch`）：改用**单个** `content~"kw"` 条件查全库（`perPage=500`），再在 `fetch` 回调里**前端按角色筛选**（`isGroup` 筛 character="group"/"group_*"；否则筛 `character===currentChar`）。`~` 单条件对中文正常。
- 实测：yan+"哈喽" 前端筛选后命中 43 条；group+"喜欢" 命中 8 条，关键词过滤生效、role/char 与渲染气泡一致。
- 局限：超高频关键词（如"你"有 29946 条）若超出 perPage=500 且集中在新时间段，可能漏掉当前角色较早的匹配（个人使用基本无碍）。
- 内联脚本通过 `new Function` 语法校验。



## Code Refactoring
- Completely split the huge `all.js` (1700 lines) into 6 modular files without changing any logic or breaking global scope:
  - `config.js`: Global variables, character lists, avatar profiles, API settings, and `PB_URL` extracted from `index.html`.
  - `utils.js`: Utility functions like time formatters (`nowTime`, `aiNowTime`, `fmtTime`) and helpers (`shuffle`, `popConfetti`).
  - `cloud.js`: Database reading/writing functions (`loadCloudChat`, `saveToCloud`, `saveToAiChat`, `loadFromCloud`, `syncCloudChats`).
  - `chat.js`: The core chat handling logic (`sendMsg`, `render`, `reGen`, stream reading, group sending, voice calling via Volcano).
  - `ui.js`: Pickers and overlays (`showModelPicker`, `openProfile`, `toggleSearch`, `showReactMenu`, `showImgPreview`).
  - `pages.js`: Everything page-related (`switchTab`, `loadMem`, health tracking, weight, period, diary rendering, checking logic).
- Wiped `all.js` clean with `// 已拆分到各模块` but kept it in place.
- Re-ordered script imports inside `index.html` (config → utils → cloud → chat → ui → pages → all) to avoid variable dependency issues.
- **Bugfix**: Fixed `Uncaught ReferenceError: renderPresets is not defined` caused by `config.js` passing an undefined function to `DOMContentLoaded`. Moved the listener to `pages.js` where the function resides.
- **Feature Update (Model Picker)**: Upgraded the `showModelPicker` UI to a two-step selector.
  - 1. User first selects an API Preset (接口通道) for the character.
  - 2. It fetches and lists the models available under that preset.
  - 3. Selecting a model saves BOTH the `preset_<char>` and `model_<char>` exclusively for that character.
- **Feature Update (Chat API)**: Created `getApiForChar()` in `chat.js` to ensure that every AI request (in single chat, group chat loop, and voice calls) correctly pulls the specific API URL, Key, and Model tied to that character's chosen preset, falling back to the global `apiConfig` if unset.
- **Feature Update (Token Usage)**: Added API Token usage tracking.
  - Modified API requests to include `stream_options: {include_usage: true}`.
  - Parsed the usage chunk from streams and stored `in_tokens` and `out_tokens`.
  - Appended per-message token stats (e.g. `消耗: 123⬆ 45⬇`) next to the message time in the chat UI.
  - Piggybacked the token data into the `thinking` field when saving to PocketBase (`<!--tokens:IN/OUT-->`) so the data persists across page reloads without requiring DB schema changes.
  - Added an "API 用量统计" panel in the Settings modal that breaks down total token consumption by model, stored locally in `api_usage_stats`.
- **Bugfix**: The `renderApiUsage()` call was missing from the active `openSettings()` function due to a duplicated function definition in `ui.js`. Added it to ensure the usage panel populates when the settings modal opens.
